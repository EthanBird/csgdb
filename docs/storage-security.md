# 存储、安全与恢复

## 1. 存储内核策略

第一阶段采用 SQLCipher 作为嵌入式事务内核，并通过独立的 `csgdb-storage` crate 静态链接。该内核承担：

- 页存储与 B-Tree；
- WAL 与原子提交；
- 基础事务隔离；
- 崩溃恢复；
- 结构化索引和约束；
- 在线备份基础能力。

Rust 层不直接向使用者暴露底层连接指针。所有 FFI 封装集中在独立 crate，并通过所有权、生命周期和线程模型限制不安全边界。

纯 Rust Pager 属于后续探索，只有在正确性测试框架成熟且基准证明必要时启动。

当前实现通过底层 `sqlite3_key` 接口在打开连接后的第一次数据库操作前设置密钥，不把密钥拼接进 SQL、PRAGMA、URI、日志或文件名。打开后立即读取 Schema 页面，以便在返回连接前拒绝错误密钥或不支持的文件。

新建数据库使用 AES-256-CBC 页加密和 HMAC-SHA256 页认证；256 位认证标签不会因性能优化而截断或关闭。已有的 HMAC-SHA512 数据库在首次配置验证失败后会以旧认证配置重新验证，成功后保持原格式读取，不执行隐式重写。错误密钥在所有受支持配置下都失败关闭。OpenSSL 3 的不可变 HMAC Provider 描述按进程缓存，引用计数由每次调用配平；包含密钥的可变认证上下文仍逐页创建并立即释放，不延长密钥相关状态的生命周期。

当前已经验证主数据库文件加密、WAL 模式的基本事务行为、四种手动 Checkpoint、自动 Checkpoint 阈值控制、有界 Group Commit，以及长快照释放后的 WAL 压力恢复和截断。临时文件、崩溃恢复、备份和跨平台 Golden Database 仍需按发布门槛继续验证，因此现阶段不能视为完整的生产安全审计。

## 2. 写入与读取

默认一个写入调度器。当前已实现的能力包括参数化语句列表的单事务批量提交、相邻参数化任务的有界 Group Commit、写入背压、手动 Checkpoint 和非阻塞自动维护：

- 合并窗口同时受最大任务数和最大等待时间限制；
- 每个逻辑任务使用 Savepoint 保持独立失败域；
- 普通写回调和维护任务作为合并屏障；
- 自动维护只使用 PASSIVE 模式，长快照不会被强制终止；
- WAL 未回收帧超过软上限时提升观测频率；
- 对高优先级状态写入提供低延迟通道；
- 对低优先级遥测应用背压；
- 后续继续接入设备空闲、电量和热状态；
- 后续基准记录提交批量和 fsync 延迟。

读取连接持有短生命周期快照。超时查询被取消，并输出可诊断的预算错误。

## 3. 加密层级

```text
Device / User KEK
        │
        ▼
Wrapped Database DEK
        │
        ├── Data Page Key
        ├── WAL Key
        ├── Index Key
        ├── Blob Key
        └── Backup Key
```

- KEK 优先存放在操作系统硬件支持的密钥库；
- 每个数据库使用随机 DEK；
- 子密钥由标准 KDF 派生，并绑定数据库 UUID 和用途；
- 便携备份密码通过内存困难型 KDF 生成包装密钥；
- 密钥版本和标识可以保存，密钥明文不得落盘；
- 修改 KEK 时优先重新包装 DEK，避免全库重写；
- 高敏感 Collection 可使用独立子密钥。

## 4. 加密覆盖

生产模式必须覆盖：

- 主数据库；
- WAL 和共享状态文件；
- 临时排序、临时表和溢出文件；
- 全文和向量索引；
- Artifact Pack；
- Checkpoint 与恢复元数据；
- 导出与备份。

如果某个平台无法保证临时文件加密，则安全模式应禁止落盘临时数据，改为内存执行或拒绝查询。

## 5. 字段级加密

数据库级加密解决文件被离线复制的问题。字段级加密用于：

- 按 Agent 或 Namespace 隔离；
- 选择性导出；
- 局部密钥轮换；
- 密码学删除；
- 限制某类查询读取明文。

字段加密在压缩之后执行。索引敏感字段时必须明确泄露模型，因为哈希、排序和确定性密文仍可能泄露相等性或顺序。

## 6. 迁移

迁移任务是可恢复状态机：

```text
Planned
  → ShadowCreated
  → Copying
  → DualWriting
  → Validating
  → Switched
  → CleanupPending
  → Complete
```

每一步均写入受事务保护的迁移记录。进程崩溃后根据状态继续或回滚。

迁移验证至少包含：

- 行数与主键集合；
- 必要字段非空约束；
- 关键索引可用性；
- 抽样内容哈希；
- 外键或逻辑引用；
- Schema 指纹。

## 7. 压缩

字段 Codec 是 Schema 的一部分：

```rust
enum Codec {
    None,
    Zstd { level: i8, dictionary: Option<DictionaryId> },
    Lz4,
    DeltaVarint,
    VectorF16,
    VectorInt8,
}
```

每条压缩数据保存 Codec 版本，允许新旧版本同时读取。重新压缩在后台按小事务分批执行，支持暂停和恢复。

高频小字段默认不压缩；大型文本、重复结构和冷数据优先压缩。向量采用专门量化，而不是通用压缩器。

## 8. Blob Pack

Artifact 内容以不可变块保存：

- 内容哈希校验；
- 分块认证加密；
- 相同作用域内去重；
- Manifest 引用计数；
- 后台 Pack 合并；
- 崩溃后未引用块清理。

数据库提交先登记待写 Blob，再写入 Pack 并完成引用切换，避免数据库引用不存在内容。

## 9. 备份

备份分为：

- 完整一致性快照；
- 增量 changeset；
- Artifact Pack 增量；
- Manifest 和 Schema 快照。

每个备份块具有版本、数据库 UUID、序号、内容哈希和认证标签。恢复前先验证完整链，不允许静默跳过损坏增量。

## 10. 损坏检测与修复

恢复顺序：

1. WAL 正常恢复；
2. 主库完整性检查；
3. 删除并重建派生索引；
4. 使用最近快照和增量恢复；
5. 最后才进入页面与记录抢救模式。

抢救输出必须标记：

- 是否完整；
- 来源页和偏移；
- 校验状态；
- 缺失字段；
- 解码使用的 Schema；
- 是否存在主键冲突。

修复工具不能承诺恢复所有数据，也不能绕过正确密钥。

## 11. 安全边界

防护目标是设备文件泄露、备份泄露、恶意动态查询、Namespace 越权和恶意数据库输入。

取得解锁后进程任意代码执行或内核权限的攻击者通常能够读取进程内明文。对此只能通过最小密钥驻留时间、权限分离和减少敏感数据加载降低风险，不能声称完全抵抗。

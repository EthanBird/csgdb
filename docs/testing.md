# 测试与发布门槛

## 1. 测试目标

数据库测试优先验证“不丢、不乱、可恢复、可解释”，然后才验证吞吐量。

## 2. 测试层级

### 当前自动化覆盖

- 默认加密、显式明文和缺少 KeyProvider 时失败关闭；
- 加密 `.db` 文件头及已知明文扫描；
- 正确密钥重开、错误密钥拒绝；
- 提交、显式回滚和 Drop 回滚；
- NULL、Integer、Real、Text、Blob 的 Rust/C 参数绑定与读取；
- 参数数量、参数索引、结果列索引和严格类型错误；
- 非法 UTF-8 Text 与原始 Blob 的区分；
- Statement 的 Ready、Row、Done、Reset 状态转换；
- 数据库句柄关闭后，存活 Statement 延迟关闭连接；
- 写入变更计数、最后插入 Rowid、自动提交、只读和事务状态；
- 忙等待参数边界与连接缓存主动回收；
- Rust 与 C API 跨线程取消真实长查询、稳定中断错误和取消后连接恢复；
- C11 头文件严格编译、动态链接和真实加密数据库烟雾测试。

### 单元测试

- 编解码器；
- Schema 指纹；
- 查询 AST 和 IR；
- 类型转换；
- Score Fusion；
- 密钥派生参数编码；
- Codec；
- 时间与有效区间。

### 属性测试

- 编码后解码保持值；
- 查询重写保持语义；
- 迁移前后逻辑结果一致；
- 压缩前后内容一致；
- 排名融合满足确定性约束；
- 任意合法状态机路径可恢复。

### 模糊测试

- 动态 AgentPlan；
- 数据库和 Manifest 解析；
- 加密页头；
- Artifact Pack；
- Schema 元数据；
- 备份链；
- 修复扫描器；
- FFI 边界。

### 集成测试

- 多连接读写；
- 长快照与 Checkpoint；
- 数据库关闭和查询取消；
- 磁盘空间不足；
- 文件权限变化；
- 错误密钥；
- 模型版本与向量维度不匹配；
- 在线迁移中断；
- 索引损坏后重建。

## 3. 故障注入

存储写入路径中的每个关键操作都应支持注入：

- 部分写；
- `fsync` 失败；
- 原子重命名失败；
- WAL 截断；
- Manifest 只写入一半；
- Blob 已写但数据库未提交；
- 数据库已提交但索引未更新；
- 进程在任意迁移状态退出；
- 系统时间回退；
- 内存分配失败。

测试框架在每个注入点重启数据库，验证：

- 已提交事务存在；
- 未提交事务不可见；
- 索引可以重建；
- Manifest 能选择最后完整代数；
- 不会将损坏状态误判为成功；
- 错误具有稳定分类。

## 4. 并发测试

使用确定性调度或模型检查覆盖：

- 多读一写；
- 读事务跨越提交；
- 取消与关闭竞争；
- 连接回收与查询流；
- 写入背压；
- 后台迁移与前台更新；
- 密钥轮换与读取。

## 5. 安全测试

- 主库、WAL、临时文件、索引、Blob 和备份明文扫描；
- 错误密钥不能返回部分可信数据；
- 密钥不出现在日志、panic 和 core dump 测试样本；
- Namespace 策略不能被 Join、子查询、图遍历绕过；
- 查询预算不能通过递归计划绕过；
- 恶意序列化计划不能造成无限分配；
- 备份重放、删除增量和顺序调换会被检测。

## 6. 兼容性测试

保存每个已发布格式版本的 Golden Database：

- 新版本必须能读取承诺范围内的旧文件；
- 迁移输出与预期 Schema 指纹一致；
- 桌面创建的文件可以在 ARM64 设备读取；
- 不同构建档位可以读取相同权威数据；
- 缺失可选索引时可以降级运行。

## 7. 性能测试

基准必须：

- 固定数据生成种子；
- 记录硬件、系统、编译器、编译选项；
- 分离冷启动和热缓存；
- 报告分位延迟而非只有均值；
- 报告峰值内存、文件大小、写放大和能耗；
- 报告向量召回率或排名质量；
- 与上一个发布版本比较。

性能回归门槛由场景设置，不能用一个总分掩盖局部严重退化。

## 8. 发布门槛

首个稳定版本至少满足：

- 所有受支持平台构建通过；
- 核心单元、属性和集成测试通过；
- 连续故障注入测试无已知数据丢失；
- 加密覆盖检查通过；
- Golden Database 兼容测试通过；
- ARM64 真机长时间测试通过；
- 文件格式、密钥格式和迁移路径已文档化；
- 不存在未说明的高严重度安全问题；
- 性能报告可复现。

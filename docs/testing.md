# 测试与发布门槛

## 1. 测试目标

数据库测试优先验证“不丢、不乱、可恢复、可解释”，然后才验证吞吐量。

## 3. 故障注入

当前已经实现两层可重复矩阵。第一层让测试子进程在指定阶段直接 `abort`，父进程要求非正常退出和精确握手标记，覆盖事务内写入、DDL 和迁移元数据恢复。第二层使用默认关闭的测试 VFS，按文件类型和第 N 次操作一次性注入 WAL 部分写、WAL 同步失败、主文件 Checkpoint 写失败和 WAL 截断失败；每次注入后均由默认 VFS 重开，检查已提交/未提交可见性、`integrity_check` 和稳定错误类别。

这两层仍不等价于设备断电，也不覆盖文件系统谎报同步成功、扇区撕裂、乱序持久化或介质静默损坏。下一层应继续覆盖：

存储写入路径中的每个关键操作都应支持注入：

- 删除和目录同步失败；
- 空间耗尽与配额变化；
- 原子重命名失败；
- Manifest 只写入一半；
- Blob 已写但数据库未提交；
- 数据库已提交但索引未更新；
- 进程在任意迁移状态退出；
- 系统时间回退；
- 内存分配失败。

测试框架在每个注入点重启数据库，验证：

- 已提交事务存在；
- 未提交事务不可见；
- 索引可以重建；
- Manifest 能选择最后完整代数；
- 不会将损坏状态误判为成功；
- 错误具有稳定分类。

## 5. 安全测试

- 主库、WAL、临时文件、索引、Blob 和备份明文扫描；
- 错误密钥不能返回部分可信数据；
- 密钥不出现在日志、panic 和 core dump 测试样本；
- Namespace 策略不能被 Join、子查询、图遍历绕过；
- 查询预算不能通过递归计划绕过；
- 恶意序列化计划不能造成无限分配；
- 备份重放、删除增量和顺序调换会被检测。

## 6. 兼容性测试

保存每个已发布格式版本的 Golden Database：

- 新版本必须能读取承诺范围内的旧文件；
- 迁移输出与预期 Schema 指纹一致；
- 桌面创建的文件可以在 ARM64 设备读取；
- 不同构建档位可以读取相同权威数据；
- 缺失可选索引时可以降级运行。

## 7. 性能测试

基准必须：

- 固定数据生成种子；
- 记录硬件、系统、编译器、编译选项；
- 分离冷启动和热缓存；
- 报告分位延迟而非只有均值；
- 报告峰值内存、文件大小、写放大和能耗；
- 报告向量召回率或排名质量；
- 与上一个发布版本比较。

性能回归门槛由场景设置，不能用一个总分掩盖局部严重退化。当前发布阻塞门采用零容忍中位 Pareto 规则：吞吐越高越好，时延、文件体积和峰值内存越低越好；任一指标回退就判定该场景失败。探索性运行可以返回成功退出码，但机器可读结果中的 `overall_pass` 仍必须保留失败状态。

当前 `benchmarks/sqlite_comparison.c` 已固定随机种子、页缓存、Schema、PRAGMA、负载和线程模型，并输出机器可读 JSON。`run_engine_comparison_gate.py` 使用 fresh database、偶数轮平衡 AB/BA、预热排除、CPU affinity、实际动态库哈希、确定性点查/范围 checksum、加密文件头和完整性检查，覆盖打开、建库、耐久写、点查、范围、更新、四读一写吞吐、读/提交分位、文件体积和峰值内存。`run_read_stress_gate.py` 对同一个不可变数据库执行旧版/新版纯读压力门，并校验实际加载库、拒绝动态链接器覆盖及相同候选产物，任何 `.db`、WAL 或共享内存文件变化都会硬失败。`run_query_gate.py` 则区分 Rust 直接准备、公开一次性标量查询和显式有界缓存路径，包含 cache-overflow 负载，并拒绝相同 A/B 产物和非法的 `p50 <= p95 <= p99` 分位关系。

正式运行至少使用一个预热对和四个测量对；发布数据默认八轮。结果必须记录确切二进制、实际加载库、命令、主机和调度顺序，不能比较不同文件系统、缓存、同步级别、负载规模或编译配置。2026-08-01 首轮结果见 [运行时性能基线](performance-2026-08-01.md)，最新查询边界见 [2026-08-02 查询性能第三轮](query-performance-round3-2026-08-02.html)。Rust `DatabasePool`、冷缓存、Checkpoint 干扰、ARM64 真机和长时稳定性仍须使用独立场景补齐，不能由这一个 C ABI 分数代替。

## 8. 发布门槛

首个稳定版本至少满足：

- 所有受支持平台构建通过；
- 核心单元、属性和集成测试通过；
- 连续故障注入测试无已知数据丢失；
- 加密覆盖检查通过；
- Golden Database 兼容测试通过；
- ARM64 真机长时间测试通过；
- 文件格式、密钥格式和迁移路径已文档化；
- 不存在未说明的高严重度安全问题；
- 性能报告可复现。

# 系统架构

## 1. 目标

CSGDB 是进程内嵌入式数据库，主要服务终端 AI Agent。系统需要同时处理：

- 小而频繁的状态读写；
- 持续追加的对话、观察和工具事件；
- 结构化事实与关系；
- 文本、向量和时间条件的混合检索；
- 大型 Artifact 的安全保存；
- 断电、崩溃、磁盘空间不足和迁移中断；
- 受限设备上的内存、CPU、I/O 与能耗预算。

## 2. 非目标

首期不实现：

- 分布式共识与多主写入；
- 云数据库服务；
- 裸机 MCU 文件系统；
- 在数据库内运行大模型推理；
- 任意深度、无预算的通用图查询；
- 用自研密码算法替代经过审查的密码学实现。

## 3. 分层

```text
┌─────────────────────────────────────────────┐
│ Agent SDK / Rust API / C ABI                │
├─────────────────────────────────────────────┤
│ CSG-Q Macro / Dynamic AgentPlan             │
├─────────────────────────────────────────────┤
│ Typed IR / Policy / Budget / Optimizer      │
├─────────────────────────────────────────────┤
│ Relational / FTS / Vector / Graph Executors │
├─────────────────────────────────────────────┤
│ Transaction / Connection / Background Jobs │
├─────────────────────────────────────────────┤
│ Storage Kernel / WAL / VFS / Crypto         │
├─────────────────────────────────────────────┤
│ Filesystem / OS Keystore / Hardware Crypto  │
└─────────────────────────────────────────────┘
```

### 3.1 API 层

提供同步 Rust API，并在其上构建运行时无关的异步适配。数据库核心不强制依赖某一个异步运行时。

对移动端和其他语言提供稳定 C ABI。Kotlin、Swift 等绑定由 C ABI 生成，不直接暴露 Rust 内部布局。

### 3.2 Schema 层

`#[derive(Collection)]` 生成：

- 稳定集合和字段标识；
- 列类型与空值规则；
- 编解码器；
- 索引描述；
- Schema 指纹；
- 迁移检查信息；
- 查询字段常量。

持久化格式不依赖 Rust 类型名和字段排列，重命名代码符号不得隐式改变磁盘格式。

### 3.3 查询层

编译期 Rust DSL 和运行时 AgentPlan 均转换为同一个逻辑 IR。优化器根据统计信息、设备能力和预算生成物理计划。

SQL 只作为可选物理后端语言，不成为公共查询协议。公共 API 不允许 Agent 直接提交任意 SQL。

### 3.4 执行层

执行器由可组合算子组成：

- 结构化扫描和索引查找；
- Join 与聚合；
- 全文召回；
- 向量 Top-K；
- 有界图遍历；
- 时间过滤和衰减；
- 排名融合；
- 投影、解释和流式输出。

每个算子必须报告估算成本，并支持取消和预算中止。

### 3.5 事务与连接

默认采用单写入调度器和多个只读快照：

```text
Writer Producers ──▶ Bounded Queue ──▶ Writer Transaction

Reader 1 ──▶ Snapshot A
Reader 2 ──▶ Snapshot B
Reader N ──▶ Snapshot C
```

设计理由：

- 避免多个写线程反复竞争文件锁；
- 允许写入合并和 Group Commit；
- 使延迟和内存占用更可预测；
- 简化嵌入式设备上的退避与背压。

不允许无限写入队列。队列满时必须返回背压、等待或按调用方策略丢弃低价值遥测事件。

## 4. 数据权威性

数据分为两类：

### 4.1 权威数据

- Event；
- State；
- Fact 与版本；
- Memory 正文；
- Edge；
- Artifact 元数据；
- Provenance。

### 4.2 派生数据

- 全文倒排索引；
- 向量索引；
- 图度数与邻接缓存；
- 查询统计；
- 摘要缓存；
- 排名校准参数。

派生数据不得成为唯一副本。恢复时允许丢弃并从权威数据重建。

## 5. 文件组织

默认采用普通 `.db` 主文件。无论数据库是否加密，扩展名保持一致：

```text
example.db
example.db-wal
example.db-shm
```

数据库 UUID、格式版本、索引代数和密钥标识存放在受保护的内部元数据中。WAL 与共享状态文件属于运行时伴生文件，数据库正常关闭或完成 Checkpoint 后可以消失。

Artifact 默认可以作为 Blob 保存在主数据库中。数据规模较大时，可显式启用外部存储：

```text
example.db
example.db.blobs/
└── segment-*.pack
```

外部 Blob Pack 必须使用独立派生密钥加密，并通过主数据库中的事务元数据引用。外部存储是性能和容量选项，不改变主数据库的 `.db` 命名。

## 6. 后台任务

统一后台调度器管理：

- WAL Checkpoint；
- 过期数据回收；
- Artifact Pack 合并；
- 压缩和重新压缩；
- FTS/向量索引构建；
- 迁移；
- 备份；
- 完整性抽检。

任务具有 CPU、I/O、内存、温度和电量预算。前台查询到来时，后台任务必须能够暂停或降低速率。

## 7. 可观测性

核心指标包括：

- 打开与恢复耗时；
- 活跃连接和快照年龄；
- 写队列长度、提交批量和 fsync 延迟；
- WAL 大小与 Checkpoint 进度；
- 缓存命中率；
- 每个查询算子的访问行数、耗时和内存；
- 向量召回数量和重排数量；
- 后台任务进度；
- 数据与索引代数；
- 错误分类和最近一次完整性检查。

默认日志不得包含密钥、明文敏感字段、完整向量或未经处理的用户内容。

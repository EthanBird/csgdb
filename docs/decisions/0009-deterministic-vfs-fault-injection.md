# ADR 0009：确定性 VFS 故障注入

- 状态：Accepted
- 日期：2026-08-01

## 背景

进程直接终止只能证明事务内核面对应用崩溃时的恢复行为，不能稳定制造一次写入只落盘一部分、同步失败、主文件回写失败或 WAL 截断失败。若测试只能依赖真实断电，故障位置不可重复，错误分类和回归定位也不可控。

公共打开接口已经保留 VFS 名称，因此可以在不改变数据库格式的前提下，在测试构建中把存储调用转发到平台默认 VFS，并只拦截指定文件类型和第 N 次操作。

## 决策

增加默认关闭的 `fault-injection` Cargo feature，并提供进程级串行的 `FaultSession`：

- VFS 名称固定为 `csgdb-fault-v1`，注册后透明转发到进程默认 VFS；
- 规则按主数据库、WAL 或任意文件定位，并按第 N 次匹配操作一次性触发；
- 首批操作覆盖完整写失败、部分写、同步失败和截断失败；
- 回调不分配、不 panic，触发后立即自动解除规则；
- 会话互斥，防止并发测试共享进程级 VFS 状态时相互污染；
- 统计写入、同步、截断、匹配和实际注入次数，使测试能够证明故障确实发生；
- I/O 扩展错误稳定映射为 `StorageWriteFailed`、`StorageSyncFailed` 和 `StorageTruncateFailed`；
- 正常构建不启用该 feature，不注册测试 VFS，也不增加默认运行路径开销。

Rust 和 C 打开接口同时正式支持选择已经注册的 VFS。名称只负责选择进程内已有实现，不加载动态代码；空名称、NUL 和超长名称在存储 I/O 前拒绝。

## 结果

优点：

- 可以重复验证 WAL 提交、主文件 Checkpoint 和截断边界；
- 失败位置和错误类别可以写成确定性断言；
- 故障后使用默认 VFS 重开，直接检查已提交可见性、未提交不可见性和完整性；
- 测试层不改变加密 `.db`、WAL 或主文件格式。

代价与边界：

- VFS 注册和规则状态是进程级资源，测试必须串行持有会话；
- 当前不模拟同步返回成功但实际未持久化、扇区乱序、介质静默损坏或磁盘空间耗尽；
- 软件故障注入仍不能替代目标设备真实掉电、文件系统和闪存控制器测试；
- 自定义 VFS 属于宿主代码能力，不应直接由不可信 Agent 输入选择。

## 后续

- 扩展删除、目录同步、journal 和空间耗尽故障；
- 将迁移状态机、Blob/Manifest 和派生索引接入相同一次性规则模型；
- 在 ARM64 目标设备执行真实掉电循环，并将结果与确定性矩阵关联。

# ADR 0008：有界类型化集合查询

- 状态：Accepted
- 日期：2026-08-01

## 背景

集合 CRUD 已经拥有稳定字段 ID、物理列名和 Rust 字段类型，但调用方若要检索多行，仍需自行编写 SQL。对终端智能体而言，直接拼接 SQL 会同时扩大注入面、无界扫描风险和 Schema 漂移风险。查询值还可能包含私有记忆，不应出现在生成的 SQL 或普通调试日志中。

## 决策

引入三阶段接口：

1. `Collection::query()` 创建不可执行的 `QueryDraft<C>`；
2. `CollectionField<C, T>` 生成 `Predicate<C>` 与 `QueryOrder<C>`；
3. 只有 `take(1..=MAX_QUERY_LIMIT)` 能生成可执行的 `CollectionQuery<C>`。

最终计划在构建时完成以下验证并固化为不可变对象：

- 所有字段元数据必须与集合 Schema 完整匹配；
- 谓词深度、节点数和排序字段数必须在固定上限内；
- 排序字段不得重复；
- 所有值必须与字段存储类型一致；
- 比较值全部使用参数绑定；
- 默认按主键升序，并在自定义排序后自动追加主键，保证结果可重复；
- 查询必须有非零且有界的结果数，不提供无界执行入口。

可执行计划拥有绑定值，但 `Debug` 只输出集合 ID、结果上限和参数数量，不输出值。`Predicate` 不实现 `Debug`，避免敏感数据被日志格式化。

## 结果

优点：

- 普通 Rust 调用在编译期绑定集合和字段值类型；
- 物理标识符只来自已派生 Schema，Agent 输入不能成为 SQL 结构；
- 查询默认具备内存上限和确定性顺序；
- 同一计划可以在单连接、事务、连接池和只读快照间复用；
- 后续 AgentPlan 可编译到同一受限 IR，而不必开放原始 SQL。

代价：

- 当前切片只支持比较、布尔组合、空值判断和排序；
- 当前返回 `Vec<C>`，虽然结果有界，但尚未提供惰性流式解码；
- 事务类型通过 `CollectionQueryExecutor` 扩展 trait 执行，因为它由存储 crate 定义，不能在上层 crate 添加固有方法。

## 后续

- 增加显式投影和主键游标分页，不引入无界 offset 扫描；
- 为 AgentPlan 增加版本化序列化、作用域、预算和能力验证；
- 增加查询取消、解释和基于注册索引的计划检查；
- 在 IR 稳定后增加属性测试和模糊测试。

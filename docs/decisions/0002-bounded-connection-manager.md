# ADR 0002：有界连接管理器

- Status: Accepted
- Date: 2026-07-30

## Context

终端智能体会同时产生状态更新、事件追加和检索请求。直接让多个线程竞争可写连接会增加锁抖动和延迟尾部；无限任务队列又会在设备降频、慢闪存或突发事件期间耗尽内存。

单连接仍然适合最小程序和由宿主自行调度的场景，因此连接管理不能成为所有调用方的强制成本。

## Decision

1. 保留现有同步单连接 `Database`，另提供可选的 `DatabasePool`。
2. 每个池只有一个可写连接，由专用线程独占并串行执行写回调。
3. 读池包含固定数量的文件级只读连接，默认 2 个，上限 64 个。
4. 写队列固定容量，默认 64，上限 65,536。
5. 队列满时由调用方选择等待、立即拒绝或限时等待。
6. `try_read` 在没有可用读连接时立即返回，不隐式扩容。
7. 读事务用于跨语句保持 WAL 快照。
8. 写回调 panic 转换为稳定错误；同池递归读和回调内同步写提交被拒绝。
9. 原始密钥或口令只解析一次，各连接在打开阶段借用同一已解析计划，不复制密钥。
10. 显式关闭要求池句柄具有唯一所有权；普通 Drop 负责安全收尾。
11. 多连接内存数据库不在当前支持范围内。

## Consequences

- 写锁竞争被集中到可观测的有界队列。
- 读取可以并行，且读 API 不能直接取得可写 `Database`。
- 突发负载不会静默扩张连接数或等待队列。
- 回调式写 API要求跨线程数据拥有所有权并满足 `Send + 'static`。
- 长时间读快照仍可能延迟 WAL 回收，需要后续 Checkpoint 策略监测快照年龄。
- 当前每个任务独立执行，尚未实现 Group Commit。

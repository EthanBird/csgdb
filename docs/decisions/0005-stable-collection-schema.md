# ADR 0005：显式稳定 Collection Schema 与指纹注册

- 状态：Accepted
- 日期：2026-07-31

## 背景

Rust 类型化接口需要同时满足两个目标：让字段编解码和 CRUD 在编译期受约束，同时保证普通代码重构不会静默改变磁盘格式。如果集合 ID、表名或列名直接来自 Rust 类型名和字段名，那么重命名、模块移动或字段重排都可能被误判为 Schema 变化，甚至创建新表。反过来，如果运行时只比较版本号，又无法识别开发者忘记提升版本但实际改变了列约束的情况。

连接池还要求类型化写入继续使用拥有所有权的参数化任务，才能保持既有背压、Savepoint 隔离和 Group Commit 语义。Schema 注册本身属于 DDL 和元数据修改，不能混入普通逻辑写入批次。

## 决策

`#[derive(Collection)]` 采用显式磁盘身份：

- 结构体必须声明稳定集合 ID、物理表名和非零版本；
- 每个字段必须声明稳定字段 ID 和物理列名；
- 每个集合必须且只能有一个非空主键；
- `__csgdb_` 表名前缀保留给内部元数据，一个物理表只能由一个集合 ID 拥有；
- Rust 类型名、字段名、模块路径和字段声明顺序不参与持久化身份；
- 泛型结构体、未支持字段类型和含糊约束在编译期拒绝。

宏生成列元数据、严格编解码、建表语句和 Insert/Get/Update/Delete 参数化语句。首批类型为固定宽度整数、浮点、布尔、`String`、`Vec<u8>` 和单层 `Option<T>`。无符号整数必须能无损表示为数据库有符号 64 位整数。

Schema 使用版本化规范描述。字段按稳定字段 ID 排序，描述包含集合 ID、表名、版本、字段 ID、列名、存储类型、可空性和主键标记；SHA-256 在编译期计算，运行时不为每次打开重复散列。

`register_collection` 在一个事务中：

1. 建立内部 `__csgdb_schema` 表；
2. 首次注册时建立物理表，或接管约束完全兼容的已有表；
3. 验证列集合、声明类型、非空和主键约束；
4. 持久化规范描述及 32 字节指纹。

已有集合的表名、版本、描述或指纹不匹配时返回 `SchemaMismatch`。实现不得覆盖旧记录、自动提升版本或猜测迁移。注册和物理检查是普通写回调，对 Group Commit 构成严格屏障。

单连接和显式事务直接执行生成的参数化 CRUD。连接池写入先生成拥有所有权的 `Value` 列表，再走现有参数化写队列，因此可以安全参与有界 Group Commit；连接池读取使用只读连接。

## 被拒绝的方案

### 从 Rust 符号自动生成磁盘名称

使用方便，但代码重构会改变持久化身份，无法满足长期文件兼容性要求。

### 只保存递增 Schema 版本

版本号不能检测遗漏升级、字段类型漂移或两个分支对同一版本作出不同定义。

### 发现不匹配后自动修改表

自动猜测 Rename、Drop、类型转换或默认值具有不可逆数据风险。迁移必须由后续显式计划描述，并具有中断恢复测试。

### 每次 CRUD 都查询注册表

可以更早发现运行期间的外部 DDL，但会给每次记录访问增加固定查询成本。当前约定在启动或组件初始化时注册，CRUD 依赖这一已验证边界；未来可以提供可选的严格漂移监控。

## 正确性与安全影响

- Rust 符号重命名和字段重排不会改变指纹；
- 约束或物理名称变化会改变指纹，即使开发者忘记提升版本也会被拒绝；
- 首次接管已有表前检查物理列，失败时注册事务整体回滚；
- 严格字段解码拒绝跨存储类转换、非法布尔值和数值越界；
- 指纹是格式身份，不是密码学数据认证；数据库页认证仍由加密存储层负责。

## 性能与兼容性影响

SHA-256 只在编译宏中运行，运行时保存固定 32 字节结果。注册需要一次短事务和物理表检查，普通 CRUD 使用静态参数化 SQL，并复用连接本地 Prepared Statement Cache。连接池类型化写入不增加新的调度队列。

当前规范格式标记为 `csgdb-schema-v1`。在首个稳定版本前仍可调整；稳定后若需改变规范编码，必须增加新的规范版本并保留旧版本识别逻辑。

## 回滚方式

类型化层位于基础 SQL API 之上，可以移除宏和注册 API，而不改变已有 SQL、Statement、事务、加密文件或 C ABI。已经创建的业务表仍是普通关系表；`__csgdb_schema` 只保存类型层元数据。删除注册记录或内部表属于显式管理操作，不能由库静默执行。

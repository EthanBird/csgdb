# ADR 0006：独立索引契约与显式事务迁移

- 状态：Accepted
- 日期：2026-08-01

## 背景

类型化 Collection 已能识别稳定字段 Schema，但业务查询还需要普通、复合和唯一索引，结构升级也需要明确的执行边界。索引既影响性能和唯一约束，又是可以从权威表数据重建的派生结构。如果把索引直接并入既有基础 Schema 指纹，给旧集合补充索引能力会改变已经落盘的格式身份；如果完全不登记索引，则无法发现同名索引指向错误表、列顺序变化或唯一性漂移。

迁移同样不能由版本号差异自动推断。添加列可能需要默认值或回填，删除和重命名可能造成不可逆数据损失；两个分支还可能为同一版本号定义不同结构。迁移需要验证明确的旧、新端点，并保证 DDL、数据转换、索引和元数据一起提交或回滚。

## 决策

索引采用独立于基础 Collection 指纹的稳定契约：

- 每个索引声明稳定索引 ID、显式物理名称、唯一性和有序稳定字段 ID 列表；
- 宏将字段 ID 解析为物理列，生成普通、复合或唯一索引 SQL；
- `csgdb-index-v1` 规范包含集合、表、索引 ID、物理名称、唯一性以及有序字段/列对，并在编译期计算 SHA-256；
- `__csgdb_index_schema` 按集合和索引 ID 保存规范与指纹；
- 注册时要求登记索引集合精确匹配，并检查物理索引属于目标表、唯一性一致、列顺序一致、使用升序和 `BINARY` 排序规则，且不是表达式或部分索引；
- 外部应用自行建立且未由 Collection 声明的索引不纳入精确集合比较。

基础 `csgdb-schema-v1` 描述和指纹保持不变。索引变化仍是版本化磁盘契约变化，必须使用显式迁移，不能在相同版本注册时静默补建。

短事务迁移使用 `migrate_collection<From, To>`：

- 端点必须具有相同稳定集合 ID；目标版本严格更大且基础指纹不同；
- 调用方提供 1 到 255 字节的稳定迁移 ID 和一个事务回调；
- 执行前验证当前注册记录、旧物理表和旧索引；
- 回调负责应用特定的 DDL、回填和数据转换；
- 回调后验证目标表，保留未变化索引、删除发生变化的旧索引并创建目标索引；
- Schema、索引注册和 `__csgdb_migration` 历史在同一事务更新；
- 回调错误、验证失败和 panic 均通过事务回滚，不留下部分历史；
- 已成功记录的同一 ID/端点返回 `AlreadyApplied` 且不再执行回调；ID 复用或当前状态冲突返回 `MigrationMismatch`。

迁移历史不保存墙上时钟时间。终端与嵌入式设备时钟可能回退或未校准，顺序由版本端点和事务提交确定。

连接池迁移作为专用写线程上的独占写回调执行，对参数化 Group Commit 和其他 DDL 形成屏障。

## 被拒绝的方案

### 将索引并入既有基础 Schema 指纹

这会破坏已落盘无索引集合的指纹兼容。独立指纹既保留基础身份，又能精确检查索引契约。

### 注册时自动对比并修改结构

即使只是添加可空列，也可能需要业务回填、部署排序和回滚策略。注册只验证，不推断迁移。

### 只记录最新版本，不记录迁移 ID

无法区分安全重试与两个不同迁移复用同一版本路径，也无法保证回调不会重复执行。

### 捕获 panic 后在同一调用中继续使用事务

展开过程中应直接销毁事务并由 Drop 回滚。尝试在未知 panic 状态下恢复并提交会扩大不确定性。

### 在首版接口中实现在线大表迁移

影子表复制、双写、增量追赶和原子切换需要持久化状态机及进程中止注入。它们属于 M6，不能伪装成当前短事务接口的自动行为。

## 正确性与安全影响

- 唯一约束和复合列顺序既由 SQLite 执行，也由注册流程验证；
- 迁移成功记录与目标 Schema 同事务提交，不会出现“历史成功但结构未更新”；
- 错误和 panic 回滚覆盖业务数据、DDL、索引及内部元数据；
- 加密数据库中的业务表、索引和内部注册表仍落在同一个加密 `.db` 及受保护 WAL 中；
- 指纹识别格式，不替代加密页认证和密钥管理。

## 性能与兼容性影响

索引和 Schema 指纹均在编译期生成。注册和迁移会读取 `pragma_table_info`、`pragma_index_list` 与 `pragma_index_xinfo`，这些成本只发生在初始化或显式维护路径；普通 CRUD 热路径不新增注册表查询。

只有 `__csgdb_schema` 的旧文件在无声明索引时可直接注册，辅助注册表会在同一事务补齐。当前迁移持有短时写事务，调用方必须控制数据量；大表应等待在线迁移 API。

## 回滚方式

索引注册表和迁移历史都是普通内部表，业务表和索引仍使用标准关系结构。移除类型层不会改变基础 SQL API 或 C ABI。已经提交的结构变化需要一条新的、方向明确的前向迁移，不能删除历史记录假装回退。
